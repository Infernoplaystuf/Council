# ============================================================
#  Council AI — Quick Install
#  Pick ONE of the sections below based on your hardware, then run
#  every line in that section in order. Each section is self-contained.
#
#  WHY MULTIPLE SECTIONS:
#  - Different NVIDIA architectures need different PyTorch CUDA wheels.
#  - llama-cpp-python (the GGUF runtime) defaults to a CPU-only build
#    when installed bare from PyPI. Each GPU section pulls the matching
#    CUDA-enabled wheel via --extra-index-url so the LLM actually runs
#    on your GPU.
# ============================================================

# ============================================================
#  SECTION E — Linux with NVIDIA GPU  (Ubuntu / Debian / Fedora / WSL2)
#  Sections B / C / D above describe the same Python + pip + conda
#  install that works on Windows AND Linux — the conda env creation
#  and the pip install lines are platform-agnostic. What CHANGES
#  on Linux is how you install the NVIDIA driver. This section
#  walks through the Linux-specific driver install and then sends
#  you to whichever of B / C / D matches your GPU architecture.
#
#  Why Linux is easier than Windows for GPU work:
#  - No hybrid-graphics MUX nonsense; the dGPU is just there.
#  - No "TF GPU is stuck on Python 3.10" lock — TensorFlow's
#    Linux GPU builds track current Python.
#  - llama-cpp-python's CUDA wheels are smaller (no MSVC redist).
#  - nvidia-smi works without extra setup.
#  - WSL2 inherits the host Windows driver — you don't reinstall
#    anything Linux-side; just enable it in WSL.
#
#  Supported distros (anything with apt or dnf and a recent kernel):
#    Ubuntu 22.04 LTS, 24.04 LTS
#    Debian 12 (Bookworm)
#    Fedora 39 / 40
#    Pop!_OS 22.04
#    WSL2 with Ubuntu 22.04+ on Windows 10 build 19044+ / 11
# ============================================================
#
#  ── STEP 1: Install the NVIDIA driver (native Linux ONLY) ──
#  Skip this entire step on WSL2 — WSL inherits the Windows-side
#  driver. You only install the driver INSIDE Linux when Linux is
#  the OS booted directly on the hardware.
#
#  Ubuntu / Debian / Pop!_OS (recommended path — apt-managed
#  drivers survive kernel updates cleanly):
#      sudo apt update
#      ubuntu-drivers devices                     # shows recommended driver
#      sudo apt install nvidia-driver-550         # or whatever is recommended
#      sudo reboot
#      nvidia-smi                                  # should print the GPU table
#
#  Fedora:
#      sudo dnf install akmod-nvidia xorg-x11-drv-nvidia-cuda
#      sudo reboot
#      nvidia-smi
#
#  Arch:
#      sudo pacman -S nvidia nvidia-utils
#      sudo reboot
#      nvidia-smi
#
#  If nvidia-smi reports a CUDA version that's TOO OLD for the
#  section you want (e.g. you want cu124 but the driver only
#  supports CUDA 12.1), upgrade the driver per the cheat sheet in
#  the "No CUDA drivers?" troubleshooting block below.
#
#  ── STEP 2: WSL2 ONLY — enable GPU passthrough ──
#  On Windows host, make sure WSL2 is up to date:
#      wsl --update
#  Inside WSL (Ubuntu shell):
#      nvidia-smi
#  If the table prints, GPU passthrough works and you can skip
#  any Linux driver install — the Windows host driver covers it.
#  If "nvidia-smi: command not found", install JUST the CUDA
#  user-space tools (NOT a Linux driver):
#      sudo apt install nvidia-cuda-toolkit-gcc   # optional, helps tooling
#
#  ── STEP 3: Install conda (if not already) ──
#  Miniforge is the lightest path (conda + conda-forge by default):
#      wget https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-Linux-x86_64.sh
#      bash Miniforge3-Linux-x86_64.sh
#      source ~/.bashrc
#  Or Miniconda is fine too (then `conda config --add channels conda-forge`).
#
#  ── STEP 4: Run the matching Windows section, verbatim ──
#  Find your GPU model in the lists at the top of Section B / C / D
#  above and run THAT section's `conda create` + `pip install` lines
#  unchanged. The conda commands and pip URLs are identical between
#  Windows and Linux. Most users want:
#
#      RTX 20/30-series, GTX 16, MX450/550:  Section B (cu121)
#      RTX 40-series, RTX 6000 Ada:          Section C (cu124)
#      RTX 50-series Blackwell:              Section D (cu128 nightly)
#
#  ── STEP 5: Verify (mirror of Sections B/C/D's last line) ──
#      python -c "import torch, simplnx, llama_cpp, chromadb, sentence_transformers, pandas, openpyxl, duckdb, h5py; print('CUDA:', torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU'); print('all imports OK')"
#
#  Should print:
#      CUDA: True
#      NVIDIA GeForce RTX <your-card>
#      all imports OK
#
#  ── Linux-specific gotchas ──
#  - "OSError: libcuda.so.1: cannot open shared object file"
#      The NVIDIA driver isn't installed or the user-space libraries
#      aren't on LD_LIBRARY_PATH. Re-run STEP 1, then reboot.
#      On WSL2 it usually means the Windows host driver is too old
#      or `wsl --update` hasn't been run since the GPU was added.
#
#  - "RuntimeError: CUDA driver version is insufficient for CUDA
#      runtime version"
#      Driver is older than the CUDA wheel needs. See the driver
#      version → CUDA cheat sheet in the troubleshooting block below.
#
#  - sounddevice/portaudio fails to install
#      Linux distros don't ship libportaudio by default. Run:
#          sudo apt install libportaudio2 libportaudiocpp0 portaudio19-dev
#          # OR (Fedora): sudo dnf install portaudio-devel
#      then re-run the pip install line. WSL2 has no audio hardware
#      passthrough — sounddevice imports fine but `sd.rec()` won't
#      hear anything. The speech tab is effectively read-only in WSL.
#
#  - Conda env activation in scripts
#      Bash scripts that `conda activate council` need `source
#      ~/miniconda3/etc/profile.d/conda.sh` first (or set
#      $CONDA_SHLVL beforehand). Not needed in interactive shells.

#    set COUNCIL_GGUF_PATH=C:\models\phi-4-Q4_K_M.gguf

#
#  Optional SQL drivers (uncomment as needed):
#    pip install psycopg2-binary   # PostgreSQL
#    pip install PyMySQL           # MySQL / MariaDB
#    pip install pyodbc            # MSSQL via ODBC
#
#  Optional simplnx plugins (orientation/EBSD, ITK image processing):
#    conda install -c bluequartzsoftware orientationanalysis itkimageprocessing -y
#
#  Verifying GPU is being used at runtime:
#    After launch, look for `[GGUF] Loading <model>.gguf
#    (n_ctx=..., n_threads=..., n_gpu_layers=99)` in the console.
#    If n_gpu_layers=0 even on a GPU machine, llama-cpp-python was
#    installed without CUDA — rerun your section's `pip install
#    llama-cpp-python --extra-index-url ...` line.
#
#  ─────────────────────────────────────────────────────────────
#  No CUDA drivers? Here's how to check, install, or skip
#  ─────────────────────────────────────────────────────────────
#  Sections B / C / D above all assume you have a working NVIDIA
#  driver. If you don't (or aren't sure), this section walks you
#  through the check, the install, and how to verify it's working.
#
#  KEY THING TO KNOW: you only need the NVIDIA DRIVER, not the
#  "CUDA Toolkit" or "CUDA SDK". PyTorch's and llama-cpp's CUDA
#  wheels bundle their own CUDA runtime libraries; the driver is
#  the only NVIDIA piece you have to install.
#
#  ── STEP 1: Check what you have ───────────────────────────────
#  Open a fresh terminal (cmd / PowerShell on Windows, bash on
#  Linux/WSL) and run:
#
#      nvidia-smi
#
#  Three possible outcomes:
#
#  (a) Command not found / "is not recognized as an internal or
#      external command"
#      → You have no driver installed OR no NVIDIA GPU. Go to
#        STEP 2.
#
#  (b) A table prints showing your GPU model and a "CUDA Version:
#      XX.Y" entry in the top-right
#      → Driver is installed. The "CUDA Version" line is the
#        MAXIMUM CUDA toolkit version your driver supports. Use it
#        to pick the section in STEP 3.
#
#  (c) Command exists but says "no devices found" / "couldn't
#      communicate with the driver"
#      → Driver is corrupted or doesn't match your GPU. Reinstall
#        the driver per STEP 2.
#
#  ── STEP 2: Decide what to install ────────────────────────────
#  If you have no NVIDIA GPU at all (Apple Silicon, AMD, Intel
#  integrated only) → use SECTION A (CPU only) above and ignore
#  the rest of this block. The app still works on CPU — just
#  slower inference.
#
#  If you have an NVIDIA GPU but no driver, install the driver
#  for your card from:
#
#      https://www.nvidia.com/Download/index.aspx
#
#  Pick "Game Ready Driver" (or "Studio Driver" — either works,
#  Studio is just slower-cadence and more stable). Choose your
#  exact GPU model + your OS + 64-bit. Download, run installer,
#  reboot. Then re-run `nvidia-smi` to verify the table prints.
#
#  Linux users: prefer your distro's package manager when possible
#  (e.g. `sudo apt install nvidia-driver-550` on Ubuntu 22.04+)
#  rather than the .run installer — apt-managed drivers survive
#  kernel updates cleanly.
#
#  ── STEP 3: Map your driver to a CUDA wheel section ───────────
#  Once `nvidia-smi` prints, look at the "CUDA Version: XX.Y"
#  number in the top-right of its output. This is the MAX CUDA
#  your driver supports, NOT the version you "have" — you can
#  always use a LOWER CUDA wheel than your driver supports.
#
#      Driver shows CUDA ≥ 12.1   → use SECTION B (cu121) for any
#                                   RTX 20/30-series / GTX 16xx /
#                                   MX450/550
#      Driver shows CUDA ≥ 12.4   → use SECTION C (cu124) for any
#                                   RTX 40-series / Ada workstation
#      Driver shows CUDA ≥ 12.8   → use SECTION D (cu128 nightly)
#                                   for RTX 50-series Blackwell
#
#  Driver version → "CUDA Version" line cheat sheet
#  (the number is the MAX CUDA supported, not the installed one):
#      Driver 525.xx → CUDA 12.1   → Section B
#      Driver 545.xx → CUDA 12.4   → Section C works
#      Driver 555.xx → CUDA 12.5   → Section C works
#      Driver 565.xx → CUDA 12.6   → Section C works (D when stable
#                                    cu128 wheels are available)
#      Driver 570.xx → CUDA 12.8   → Section D
#
#  Driver too old? Update it from the NVIDIA Download page above.
#  Updating the driver is a download + installer + reboot —
#  doesn't touch anything in your conda env.
#
#  ── STEP 4: Verify after install ──────────────────────────────
#  After running your chosen Section (B / C / D), the final
#  `python -c "import torch ..."` line in that section prints:
#
#      CUDA: True
#      all imports OK
#
#  If you see `CUDA: False`, something is off. Common causes:
#
#  - Driver not installed yet → see STEP 1 / 2.
#  - Driver too old for the wheel you picked → see STEP 3 chart.
#  - Wrong PyTorch wheel for your driver → uninstall + reinstall
#    with the right --index-url for your CUDA version:
#
#        pip uninstall torch torchvision torchaudio -y
#        pip install torch torchvision torchaudio --index-url \
#            https://download.pytorch.org/whl/cu121   (or cu124, cu128)
#
#  ── STEP 5: Verify llama-cpp is using GPU at runtime ──────────
#  When the app loads a GGUF model, look at the console for:
#
#      [GGUF] Loading <model>.gguf (n_ctx=..., n_threads=...,
#                                    n_gpu_layers=99)
#
#  If `n_gpu_layers=0` on a machine where `torch.cuda.is_available()`
#  is True, that means PyTorch found the GPU but llama-cpp didn't.
#  Cause: llama-cpp-python was installed as the CPU build (the bare
#  PyPI version). Fix by re-running ONLY the CUDA-specific
#  llama-cpp install line from your section:
#
#      pip install llama-cpp-python --extra-index-url \
#          https://abetlen.github.io/llama-cpp-python/whl/cu121 \
#          --force-reinstall --no-cache-dir
#
#  (Use cu121 / cu124 — whichever matches your section.)
#
#  ── STEP 6: I just want it to work without a GPU ──────────────
#  Skip everything above and use SECTION A. The app is fully
#  functional on CPU — every feature works, just slower inference
#  (~1-5 tokens/sec on a 7-8B model vs 30-60 tokens/sec on a
#  modern GPU). On CPU, pick a smaller GGUF — the Llama-3.2-3B-
#  Instruct Q4_K_M model recommended in the "After install" block
#  below is a good first choice.
#
#  ─────────────────────────────────────────────────────────────
#  Common conda+pip conflicts (and how to fix them)
#  ─────────────────────────────────────────────────────────────
#  Symptom: `import simplnx` fails with `_ARRAY_API not found` or
#           `numpy.dtype size changed`.
#  Cause:   pip upgraded numpy to 2.x; dream3dnx was built against 1.x.
#  Fix:     conda install -c conda-forge "numpy<2.3" -y
#
#  Symptom: `import simplnx` crashes with `HDF5 library version
#           mismatched error`.
#  Cause:   PyPI h5py and conda dream3dnx loaded different HDF5 DLLs.
#  Fix:     pip uninstall h5py -y && conda install -c conda-forge h5py -y
#
#  Symptom: Random `OMP: Error #15: Initializing libiomp5md.dll`.
#  Cause:   Two OpenMP runtimes loaded into one process.
#  Fix:     set KMP_DUPLICATE_LIB_OK=TRUE   (last-resort workaround)
#           or reinstall scipy/numpy from conda-forge to use MKL OpenMP.
#
#  Symptom: `DLL load failed while importing simplnx` (Windows).
#  Cause:   MSVC runtime mismatch between conda dream3dnx and a pip wheel.
#  Fix:     Microsoft Visual C++ 2015-2022 Redistributable — install
#           the x64 version from microsoft.com.
# ─────────────────────────────────────────────────────────────
