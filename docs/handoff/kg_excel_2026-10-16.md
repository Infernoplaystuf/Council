"I want to make sure that knowledge graphs can handle excel files to help in data
consumption like for the ledger tab". Their answers:

1. Read BOTH the Ledger's reviewed parent CSV (the values the user accepted) AND raw
   workbooks with the Ledger's own readers (all sheets, text boxes, charts, pictures via
   Tesseract, .xls/.xlsb/rights-protected through Excel).
2. LINKS ONLY: people, parts and projects stay the only node kinds; each ledger row is
   evidence on links (inspector - part - project) pointing at its workbook, sheet and cell
   (or the parent CSV row).
3. Inspector initials: the Ledger's alias list; unknown initials asked once through the
   graph's name questions; never guessed.
4. Its own branch, merged into qt-migration after adversarial review and the full suite.

Later the same day, relayed from the Ledger session at the user's request: let users add
folders OUTSIDE the vault as extra read-only sources, chosen in the Connections tab.

## What changed (read before editing)

- **New `council_core/kg_excel.py`** (toolkit-free): `read_ledger` (a parent CSV with its
  `.schema.json`), `read_workbook` (the Ledger's `load_workbook_grids` + a row-by-row grid
  reader), `preview`, `describe`. Design notes are in its docstring.
- **`knowledge_graph.py`** (schema still **v3**, no new table or column):
  - predicate `INSPECTED` (person -> part); built-in rules `LEDGER_PART`, `INSPECTOR`,
    `SHEET_PART` (bracketed labels, never stored in `field_rules`);
  - `Value.tentative` (only the Ledger's reading says it -> the link stays `suggested`),
    record kinds `ledger`, `sheet`, `picture`, and an in-memory `reading` record;
  - `read_records` sends workbooks and Ledgers to kg_excel; doc_cache `records` may now be
    a dict (`{"v": 2, "records", "labels", "summary", "notes", "error"}`) - the old list
    form still loads; a workbook that can never be read (a password, not a workbook) is
    cached with its reason so Excel is not started for it on every rebuild;
  - a Ledger's content hash covers its CSV, schema and review workbooks;
  - review kind **`initials`** (one question per initials, candidates offered, never
    picked); `add_person(name)`; `_seed_records` keeps bare initials out of the
    full-name pass;
  - locators may carry `cell`, `cells`, `header`, `image`, `item`, `from`, `sources`;
    a workbook text line is `(sheet name, row, text)` - `page` is a str there;
    `locator_text` words them ("sheet Build, cell B4 (Freq (kHz))", "row 5, Flaw # 1A
    (…) — from nde.xlsx › Part 101!C4");
  - text chunks carry `line_nos` (a workbook's rows are not contiguous) and
    `suggest_from_text` uses them;
  - `neighbors(evidence_limit=)`, `evidence(limit=)`, `mentions(limit=)`,
    `mention_count`, `sources()`, coverage fields `ledgers/workbooks/pictures/notes`;
  - **extra folders**: `add_root` / `remove_root` / `extra_roots` (meta key
    `extra_roots`), document paths `<rootid>/rel` for them (`abs_path`, `display_path`),
    and `"file"` (the display path) in evidence / mention / review / source dicts.
- **Connections tab**: "Spreadsheets" (each Ledger / workbook in plain words, and why one
  was not read), "Folders…" (`FoldersDialog`), the initials question with "Someone else -
  type their name…", evidence capped per link (`EVIDENCE_SHOWN`) with "… and N more",
  workbook previews on a worker thread.
- **Ledger seams** (small, default behaviour unchanged): `source_extract.load_workbook_grids(
  ..., want_pictures=True)`, `source_extract.load_people(csv)` (the new optional `"people"`
  section of `<parent>.aliases.json`), `save_aliases` keeps other sections of that file.
