consumption like for the ledger tab". Their answers:

   graph's name questions; never guessed.
4. Its own branch, merged into qt-migration after adversarial review and the full suite.

Later the same day, relayed from the Ledger session at the user's request: let users add

  - a Ledger's content hash covers its CSV, schema and review workbooks;
  - review kind **`initials`** (one question per initials, candidates offered, never

  - locators may carry `cell`, `cells`, `header`, `image`, `item`, `from`, `sources`;

  - text chunks carry `line_nos` (a workbook's rows are not contiguous) and

  - `neighbors(evidence_limit=)`, `evidence(limit=)`, `mentions(limit=)`,

  - **extra folders**: `add_root` / `remove_root` / `extra_roots` (meta key

## Review (iii), 2026-10-18: the picture rule

An adversarial review of the picture rule (`7e32be3..83f80b9`). Each finding was written
as a failing test (`b312683`, the `test_r3_*` tests), then fixed.

| severity | what was wrong | fix |
|---|---|---|
| HIGH | a picture's `Project ID / Project Name` row (read at 40%) renamed another source's firm link | picture records feed no ID-name pairs |
| HIGH | a CSV's `D. Whitfield` was guessed to be a picture's Dana Whitfield, and that guess then "confirmed" the picture | picture names explain no initials; a guessed person is not known elsewhere |
| HIGH | confidence was looked up by word text: a misread `PN-7`+`7` took 97% from a sure `PN-77` elsewhere | Tesseract's confidence by box position, cell by cell |
| MEDIUM | a column title or form label read at 12% still decided whose link it was | the value's confidence is the lower of it and its title / label |
| MEDIUM | the clipboard check refused a list (pictures, files) and let HTML, RTF, JPEG and others be lost | an allow-list of plain text formats; Remote Desktop refused |
| MEDIUM | the user copying during a rebuild had their copy overwritten by the restore | careful mode: the change counter is watched; the clipboard is left alone |
| MEDIUM | the Ledger and the graph copying at once put back each other's pictures | one lock for picture copies in the process |
| MEDIUM | "rebuild again later to read them" never came true: an unchanged workbook was not read again | `pictures_pending` makes the next safe rebuild read it, and the graph phase is not skipped |
| LOW | "every name found elsewhere" was said of a link left suggested for another reason | worded from the link's final status |
| LOW | a merge the user made did not count as known | compared as merged |

Checked with the real Excel here: opening a workbook hidden does not move the clipboard's
change counter (926 before and after), so careful mode does copy when nothing else
happens. Not checked: Phone Link and third-party clipboard managers (they would make the
counter move, so pictures wait - the safe direction).

## Decisions made here (tell the user)

- **Pictures are read everywhere, and trusted only when confirmed** (the user,
  2026-10-18: "have the knowledge graphs try to read the images but maybe not have the
  data from the images be 100% trusted unless we are positive that the data pulled from
  the images is accurate").
  - Pictures in Excel-only workbooks (.xls, .xlsb, rights-protected) are copied out
    through Excel and the clipboard when Tesseract is installed and the clipboard is safe
    to use (`excel_open.clipboard_safe`): Windows does not sync it to other devices, this
    is not a Remote Desktop session, and it holds plain text only (formats 1, 7, 13, 16 -
    the only thing put back). The graph reads **carefully** (`read_with_excel(careful=
    True)`): when the clipboard's change counter moves while the workbook is read (the
    user copied something), no more pictures are copied and the clipboard is not put
    back over the user's copy. Pictures not copied are counted with the reason, and the
    workbook is read again at a later rebuild once the clipboard is safe
    (`summary["pictures_pending"]`). Windows clipboard history, if on, may keep the
    copied pictures (on this PC).
  - One picture copy at a time in the process (`excel_open._CLIPBOARD_LOCK`), Ledger
    included; the Ledger now saves the user's text when it takes the lock (its first
    picture) instead of before opening the workbook. Otherwise its behaviour is unchanged.
  - A link that rests on a picture is firm only when every value it rests on, and the
    column title or label it hangs on, was read at least `PICTURE_SURE` = 90% sure
    (Tesseract's confidence for that cell, by position -
    `source_extract.rows_with_confidence`) **and** every one of its people, parts and
    projects is known from a source that is not a picture, as merged and not guessed
    from initials. Otherwise it is suggested. A picture's ID | Name row renames nothing
    and its full names explain no initials elsewhere. The evidence says which: "read
    from a picture, 92% sure, every name found elsewhere" or "62% sure — check it". A
    link another source states is firm whatever the picture says.
  - (Superseded: on 2026-10-16 the graph did not copy Excel-only workbooks' pictures at
    all.)
- A Ledger's own people list is preferred over an answer given "everywhere"; an answer
  for one document beats both.
- Only the parent CSV is the user's word. Review workbooks are never read as sources:
  they are used only to say where an accepted value came from.

## Still open

- Several people per initials across Ledgers: two Ledgers that give one set of initials
  to different people make it a question for any workbook that is not one of them.
- A table header with only one rule column in a row of two cells (a two-column parts list
  `Part Number | Description`) is read as a labelled value, not a table.
- The graph phase is still one transaction: while it runs, other opens get "busy".
- A Ledger outside the vault is read only when its folder is added (Folders…).
- The preview of a far row of a big workbook takes seconds (it runs on the worker).
- The Excel watchdog stops only a stuck open, not a stall while copying cells; the
  terminal's "still working" line shows such a stall.
